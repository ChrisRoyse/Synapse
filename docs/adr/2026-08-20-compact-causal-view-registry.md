# Compact causal-view Registry under a bounded CPU runtime

Date: 2026-08-20
Status: accepted for issue #2260

## Context

The action Oracle was below its grounded sufficiency threshold. The prior panel
contained high-dimensional nested projections of the same request and admission
objects, while the information needed by the estimator was often present only
as explicit categorical boundaries inside those objects. Adding more opaque
vectors would increase memory, pair count, and pseudo-replication without
creating new pre-trigger facts.

Poly demonstrated a useful registry discipline: enumerate several frozen views
of each physical atom, bind their extractor semantics and source boundary, and
refuse monotone-equivalent candidates before expensive measurement. Its full
F1–F10 runtime was not complete, so Synapse adopts the contract model rather
than treating unfinished candidate transforms as measured capabilities.

## Decision

Synapse publishes a content-addressed causal-view Registry for the action panel.
It contains ten F1–F10 candidate contracts for each of eleven physical
pre-trigger atoms. At the current sample size, exactly one deterministic,
compact producer is serving for each powered atom. The resource-pressure view
is collected but remains `parked_underpowered` until a later, immutable,
statistically powered promotion.

Each contract binds:

- the physical parent atom and exact source JSON/schema boundary;
- the frozen Calyx lens identity and canonical `LensSpec` digest;
- an extractor-schema digest covering ordered vocabularies and formulas;
- output type, dimension/cardinality, equivalence ownership, lifecycle, and
  estimator compatibility;
- pre-trigger-only status and exact CPU/GPU/vector/matrix resource accounting.

Candidate transforms are within-atom alternatives. They are not temporal causal
streams, never form sibling pairs, and cannot multiply the causal graph. The
existing PC-stable, partial-correlation, transfer-entropy, bidirectional
Granger, lag-correlation, CCM, cross-K, Hawkes, and BH-FDR map operates only on
admitted physical stream representatives.

Registry content is stored in Calyx Registry CF and atomically bound to an
Assay ledger entry. Its identity covers the panel watermark, the Anchors-CF
frontier, catalog, measurement contract, association policy, resource proof,
and measured evidence. An unchanged Registry request point-reads and verifies
that artifact before any estimator work; a changed frontier requires an
explicit new measurement.

Registry schema v5 separates three facts that must never be conflated: the
panel's declared slots, the finite rectangular slots physically carried by
every record in the writer-sealed slot-125 cohort, and the subset that can enter
the logistic estimator. A view that is exactly constant in the observed cohort
remains physically available and receives an explicit analytical incremental
information value of zero for that cohort; an estimator-degenerate sketch stays
unmeasured and receives no invented value. Missing, ragged, non-finite, and
withheld views remain distinct typed states. Caller exclusions cannot name an
unknown lane or any frozen predictor cause.

Readiness schema v7 keeps the full fourteen-slot predictor contract intact and
authenticates a second exact partition: estimator-backed sufficiency slots plus
observed-cohort constants must be disjoint and must cover the full predictor.
KSG bits and panel sufficiency run only on the informative subset, while
serving still validates and consumes every physical cause. No Assay Lens row is
fabricated for a constant. The canonical readiness publisher fixes the cohort,
20,000-row bound, KSG k=4, and exact non-predictor exclusion set; a different
instrument requires a new persistence generation.

The action predictor is lowered at validation time into a bounded,
content-addressed Blob. Serving point-reads that Blob, measures only the query,
uses the same typed per-slot RRF implementation as chronological replay, and
requires query-local per-slot Guard acceptance, at least three grounded
neighbors, a normalized vote-separation floor, and a confidence capped by
sufficiency, Guard calibration, Goodhart stability, and regression closure.
Validation, readiness, Registry, predictor, Guard, Blob, and Answer identities
are all ledger-bound.

The public shell path publishes and independently reads a canonical
`command_audit` intent before any process boundary, carries that exact measured
constellation id into the typed Oracle, and records the decision in the final
audit. While readiness is absent, false, or stale, causal autonomy is explicitly
not armed and the existing operator-plus-allowlist policy remains the named
authority; the system does not manufacture a prediction. Once readiness is
true, an Oracle error or negative prediction refuses before process creation.
A refused, unattempted action is persisted as `causal_refused_unobserved` and
produces no Reward, guard-region anchor, or recurrence observation, preventing
the predictor from creating its own training labels.

Registry, readiness, and Answer publication re-read their exact physical source
revisions inside the durable commit boundary and again after physical readback.
Movement before commit writes nothing; movement immediately after commit keeps
the historical ledger fact attributable but refuses to serve it as current.
Qualified slot writes on a grounded constellation atomically re-publish and
byte-verify its existing Anchors rows, so the Anchors change signal is also the
O(1) grounded-causal-content frontier. New unanchored intents deliberately do
not invalidate a trained artifact; a grounded slot rewrite does.

RRF gives equal physical score ties the same competition rank, carries a full
tie group across the per-slot cutoff, and returns `Insufficient` when a fused
tie crosses the final outcome-evidence cutoff. `CxId` orders presentation only;
it never selects outcome evidence. The action Guard has a separate minimal
writer-sealed roster (command shape, environment state, request-identity
policy, allow-shell policy, and executable resolution). Multi-slot Ward
calibration row-aligns exact case identities and conformally certifies the
actual `AllRequired` policy score. Per-slot FAR remains diagnostic; the
independently replayed combined FAR is readiness authority.

## Resource policy

All new causal views are CPU scalar/one-hot operations. The Registry contains no
materialized vectors or pair matrices. Sibling candidates are metadata-only;
assays are explicit, bounded, and single-frontier. No CUDA, model-lens,
embedding-runtime, cuVS, CUDA-PQ, WGC, DXGI, or D3D capture feature is present in
the shipped daemon feature graph.

The installed Windows process tree is placed under a page-aligned
949,997,568-byte aggregate committed/private Job limit and a 25% CPU hard-rate
limit. The daemon's nested Job has exact process and aggregate committed/private
limits of 789,999,616 bytes. No Job working-set bound is installed: the
configured launch token cannot set that privilege-dependent branch, which would
remain per-process rather than an aggregate resident-page limit. Physical
working set is retained as measured telemetry and a separate runtime Source of
Truth, never represented as a kernel guarantee.
GDI `BitBlt` uses no explicit GPU API but may be accelerated by Windows or the
display driver, so physical per-process GPU memory is also a separate runtime
Source of Truth.

## Consequences

- Transformations can expose existing signal to a finite-sample estimator but
  cannot create absent causal facts; genuine remaining entropy deficits require
  new pre-trigger sensors.
- Small-sample candidate selection is frozen and reports `underpowered`; no
  apparent winner is data-mined from the outcome.
- Later promotion must demonstrate incremental conditional information under a
  predeclared multiple-testing family and mint new content identities.
- Readiness remains honestly `not_ready` whenever measured serving-panel bits
  remain below outcome entropy.
- Predictions never become their own grounded outcomes: only an actually
  attempted action may publish an execution Reward.
- Unsupported capture or resource semantics fail with typed remediation rather
  than selecting an alternate backend.
