No automated tests, FSV scripts, FSV harnesses, benchmarks, CI, or GitHub Actions were used. Supporting commands in this record are structural checks only.

## Research

- Exa and native web research both pointed to event-sourcing/CQRS guidance: the append-only event store is the system of record, while materialized views are deterministic read projections that can be regenerated from the durable log. Sources: https://learn.microsoft.com/en-us/azure/architecture/patterns/event-sourcing and https://learn.microsoft.com/en-us/azure/architecture/patterns/cqrs.
- Exa and native web research also pointed to OpenTelemetry log-model guidance: erroneous conditions should be distinguishable by severity and structured attributes. Source: https://opentelemetry.io/docs/specs/otel/logs/data-model/.

Design consequence for this batch: Synapse raw CF rows remain the physical write-side SoT, and Calyx native rows are deterministic read-side projections with explicit panel names, panel versions, source CF/key metadata, and fail-closed error logging when measurement cannot be produced.

## Root Cause

1. `synapse-storage` only had native Calyx constellation builders for timeline, episode, agent-event, and agent-transcript rows. The action, reflex-audit, process-history, and observation writers persisted raw CF rows but never measured native Calyx projections.
2. The first panel implementation used durable slot ids above the supported CF tag budget. Real action measurement failed with `slot id 48 exceeds durable CF tag maximum 47`.
3. Empty optional sparse observation features could create zero-vector lens input, causing `CALYX_LENS_NUMERICAL_INVARIANT`.
4. Process recency rank passed epoch milliseconds to a lens bound that expects micro-units before internal scaling. Real process launch failed after the raw write with `syn scalar rank input 1784340870413 outside frozen range [0, 4102444.8]`.
5. Setup installed-health inspection used stale/rotated startup-log signals and a fixed deadline, so a live, slowly progressing Calyx startup could be rolled back. Rollback could also retain the escalation worker because a long await was not shutdown-cancel aware.
6. The public 40-tool MCP surface had no client-parity route for reflex registration/history, so reflex audit verification could not use the real wired client without adding a typed facade route.

## Implementation

- Added `syn-action-v1`, `syn-reflex-v1`, `syn-process-v1`, and `syn-observation-v1` panel builders in `crates/synapse-storage/src/constellations.rs`.
- Added a durable slot-budget validator that rejects any durable panel slot id above `47` before write.
- Added action/reflex/process/observation write-through APIs in `synapse-storage` and wired the real raw CF writers in `synapse-reflex` to measure native Calyx rows after raw persistence.
- Added structured error logs for each panel measurement failure, with source CF and source key metadata.
- Encoded empty optional observation sparse groups as `Absent(NotApplicable)` instead of producing zero vectors.
- Added default sampled observation projection policy: `SYNAPSE_CALYX_OBSERVATION_SAMPLE_EVERY_N`, default `10`, with malformed/zero config failing closed.
- Added numeric `launched_at_unix_ms` and `ts_ns` to process launch history rows.
- Fixed process and timeline/episode rank bounds with explicit micro-unit constants.
- Updated setup installed-health progress handling to inspect only current startup-log evidence, extend the deadline only for same-candidate progress, and print bounded diagnostic fields.
- Made escalation shutdown cancel long pending/orphan-removal awaits.
- Added typed `routine` facade operations for reflex register/cancel/list/history so reflex audit FSV can use the real 40-tool MCP client surface.
