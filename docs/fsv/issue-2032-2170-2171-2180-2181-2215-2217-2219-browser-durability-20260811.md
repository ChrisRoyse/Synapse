## Root causes and fixes

### #2032 — close acknowledgement overruled physical state

The close path reported a failed/lost acknowledgement even when Chrome had
already removed the tab. Completion now comes from an independent bounded tab
enumeration: absent means physically closed; still present means not closed; an
unreadable/ambiguous after-state fails precisely. It never retries a destructive
close merely because its acknowledgement was lost.

### #2170 — output limits were applied after peak allocation

`pageScreenshot` retained every base64 tile and Rust allocated the complete
unscaled bitmap before `max_pixels`/`max_long_edge` was honored. The geometric
400-tile bound was not a memory bound. The replacement planner computes encoded
tile, decoded tile, stitched bitmap, native-message, and peak-live bytes before
the first capture/page mutation and rejects an over-budget transaction with
`CAPTURE_PLAN_EXCEEDS_LIMIT`. The extension sends each tile through an
acknowledged bounded handoff instead of retaining the complete base64 set, and
Rust independently recomputes and enforces the same budgets before allocation.
The memory budget is therefore an invariant at both trust boundaries, not an
estimate accepted from the extension.

### #2171 — caller timeout released an uncancellable operation

`chrome.tabs.captureVisibleTab()` returns a Promise with no cancellation input.
The old timeout race released the global queue in `finally` even though the raw
Chrome Promise could still be running. The lease is now bound to that exact raw
Promise until it physically settles. A caller deadline records
`callerTimedOut=true` but cannot release/relabel the slot; a second call receives
`CHROME_CAPTURE_VISIBLE_TAB_PENDING` with the same lease and does not start a
capture. Late fulfilled bytes are discarded. Quota timing is based on raw-call
start evidence and the extension exposes the bounded lease/last-settlement state
for independent inspection.

### #2180 — one sharing violation destroyed the only encoded evidence

Artifact writers performed one `rename` and deleted their staging file on any
error. This made a transient Windows share violation terminal and erased the
only bytes useful for diagnosis. Screenshot, PDF, and download publication now
share one same-directory atomic publisher. It flushes/closes the owned writer,
reopens and hashes the staging bytes, retries only Windows sharing/access
contention within a bounded budget, and verifies the final bytes after rename.
Terminal failures retain the exact evidence under a bounded quarantine name; if
even quarantine rename is blocked, the exact staging file remains and is named.
It never copies non-atomically or switches capture backend.

### #2181 — a fixed daemon timeout hid the typed transaction deadline

The screenshot bridge used an unrelated fixed 30-second response envelope.
That masked the extension's caller deadline/lease verdict and serialized later
commands behind the daemon's delivered-command gate. The daemon now derives its
envelope from the validated screenshot transaction budget plus explicit
rollback/terminal-ack headroom. Delivered mutation ownership is retained until
terminal acknowledgement, while the raw-capture lease remains independently
owned until raw settlement. Requested/effective deadline, phase, lease, and
remediation survive to the public error.

### #2215 — duplicated declarations had no build agreement gate

The daemon and service worker each declared a bridge build ID and SHA, but the
build only attested their bytes independently. `synapse-mcp/build.rs` now parses
both source declarations, requires exact ID agreement, requires identical
64-character lowercase hexadecimal declared SHAs, and registers both files as
Cargo rerun inputs. This is deliberately separate from runtime verification of
the installed worker's physical SHA.

### #2217 — a lossy wildcard recategorized valid extension errors

JavaScript could emit codes Rust did not recognize; Rust's wildcard converted
every such authenticated response to the unrelated `A11Y_CDP_ATTACH_FAILED`.
Both sides now carry an explicit trusted registry, and the canonical lint gate
requires exact cross-language agreement. Registered codes survive unchanged.
An unregistered/missing code becomes
`CHROME_BRIDGE_ERROR_CODE_CONTRACT_VIOLATION`, preserving the received code,
original detail, and exact repair guidance. It is never treated as attach loss.

### #2219 — a valid response exceeded the route's implicit 2 MiB limit

The planner permitted a 60 MiB native message, but the exact Axum JSON route
inherited its 2 MiB default. A valid multi-megabyte response therefore died as
HTTP 413 before the handler, and the extension tore down a healthy WebSocket so
the caller saw transport loss. The route now has an explicit 64 MiB body limit.
The service worker measures the complete serialized outer JSON body with
`TextEncoder` before fetch and emits
`CHROME_BRIDGE_MESSAGE_BODY_EXCEEDS_LIMIT` with measured/allowed bytes.
Planner, HTTP, JavaScript, Rust, and lint share mechanically checked constants.
Deterministic 4xx responses preserve status/body and do not reconnect; only a
classified network/auth/server failure can replace the command transport.
