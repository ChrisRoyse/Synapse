# Issues #2189, #2190, #2197, and #2198 FSV — bounded ordered projections

Date: 2026-08-10 America/Chicago

## Defects and root causes

### #2189 — transcript health performed a retained-corpus scan

The dashboard/health transcript snapshot decoded and sorted every retained row
in `CF_AGENT_TRANSCRIPTS` to return at most 50 records. Production held 50,973
live rows, so a bounded response still paid an unbounded scan, decode, and sort.
The source CF is keyed by spawn and line identity, not timestamp, and therefore
cannot answer newest-first reads without a second access path.

### #2190 — reflex history and lifecycle were reconstructed by full audit scans

Global reflex history, terminal lifecycle reconstruction, and the recursion
clamp counter repeatedly scanned and folded `CF_REFLEX_AUDIT`. The source key is
reflex-local rather than globally time-ordered. There was no durable global
order or aggregate state, so read cost grew with the retained audit corpus.

### #2197 — scheduler replacement reset existing lifecycle timestamps

Registering any new reflex rebuilt the scheduler. The replacement scheduler
initialized every status row from one fresh `Utc::now()` value before the prior
lifecycle fields were copied. Registering reflex B therefore changed reflex A's
`registered_at`, even though A had not transitioned.

### #2198 — projection reconciliation was cached for the process, not the vault

Manual multi-vault verification exposed a second fail-open defect. Each new
projection used one process-global `AtomicBool`. After vault A reconciled, vault
B inherited `true` and skipped its own source/index proof. That cache contained
no vault path or generation identity.

## Independent research after diagnosis

`pwsh -File scripts/check-research-lane.ps1` reported Exa MCP `live`; its real
query path and the built-in web lane were both used. Primary sources read:

- FoundationDB's index guidance models a secondary index as another ordered
  keyspace updated in the same transaction as the source:
  <https://apple.github.io/foundationdb/simple-indexes.html>.
- FoundationDB's online-index guidance requires concurrent writes to update the
  new index while a resumable backfill covers existing rows:
  <https://github.com/apple/foundationdb/wiki/Best-way-to-add-an-index-on-already-existing-data>.
- CockroachDB's online-schema-change description likewise separates mutation,
  backfill, and validation before publication:
  <https://www.cockroachlabs.com/blog/how-online-schema-changes-are-possible-in-cockroachdb/>.
- Rust documents `AtomicBool` as one atomic boolean, not keyed state, while
  `Mutex` protects structured shared state:
  <https://doc.rust-lang.org/stable/std/sync/atomic/struct.AtomicBool.html> and
  <https://doc.rust-lang.org/stable/std/sync/struct.Mutex.html>.
- Rust's named thread builder supports explicit thread construction and startup
  failure propagation, which informed the scheduler replacement boundary:
  <https://doc.rust-lang.org/stable/std/thread/struct.Builder.html>.

Applied rule: source rows and ordered pointers commit atomically; old data is
backfilled resumably and validated as an exact set; aggregate projections are
validated against a complete fold; readers are strictly bounded; corruption is
an error, never a scan fallback. A fast reconciliation cache is permitted only
for the exact open `(vault_dir, vault_id)` identity whose proof succeeded.

## Implementation

- Added append-only storage IDs without renumbering any existing ID:
  `CF_AGENT_TRANSCRIPT_ORDER` is `0x...12`; `CF_REFLEX_AUDIT_ORDER` is
  `0x...13`.
- Ordered keys encode reverse timestamp plus exact deterministic tie fields.
  Values contain the source key and source-value SHA-256. Every read point-reads
  the source, verifies the digest, decodes it, and recomputes the ordered key.
- Transcript ingest revision-guards and commits source/index rows in one Calyx
  atomic multi-CF write.
- Reflex writes atomically commit source, order, per-reflex folded state,
  registry, and recursion-clamp aggregate.
- Both projections use resumable progress, build metadata, complete source/index
  set reconciliation, and no fallback path.
- Dashboard transcript reads are capped at 50; reflex global history is capped
  at 1,000. A four-times bounded candidate window detects fragmented expiry
  pages instead of silently scanning onward.
- Scheduler replacement seeds the preserved lifecycle fields into shared status
  before the new tick thread can start.
- The process fast path now stores `Option<(PathBuf, vault_id)>` under the same
  projection mutex. Vault status is read first. Closed/missing identity is a
  structured error; another path or another generation at the same path must
  reconcile independently. The cache is updated only after successful proof.

returned zero. The populated source began `201/0`; opening it after the empty

`AGENT_TRANSCRIPT_ORDER_LIMIT_EXCEEDED`.

### Edge 2 — atomic new ingest and lifecycle transitions

A new transcript with known maximum timestamp and identity
`agent-spawn-new-ingest/7` changed physical counts `201/201 -> 202/202` and was
the exact first row. Reopening the vault in another process preserved `202/202`

The reflex sequence wrote register/register/clamp/cancel/reactivate/cancel/cancel
after the legacy row. Counts ended `8/8`; the clamp projection was exactly one
and the complete source fold was exactly one. The first cancellation exposed A
as terminal, reactivation removed A from terminal state, and the final fold
contained A and B cancelled with A's updated priority 501. A separate process
reopen returned history/source `8/8`, terminal count two, and clamp `1 == 1`.

For transcript, the oldest order row outside the newest-200 candidate window was
